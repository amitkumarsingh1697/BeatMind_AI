# Testing strategy

| Item | Value |
| --- | --- |
| Version | 0.1 (Batch 2), 2026-10-28 |
| Perspective | QA lead |
| Scope | MVP (PRD v2.1), all components in TDD v2.0 |

| Status | Draft. No tests exist yet (DEC-001). |

## 1. Principles

1. **Every requirement has at least one test** in the RTM before its feature is called done.
2. **Automate by default.** Manual tests are kept for listening quality, screen readers and real devices.
3. **Test the money and the rights paths hardest.** Billing, credits, ownership state and certificates are where bugs cost users and the company the most.
4. **Model behaviour is tested like a dependency that can regress.** Every model or version change reruns the model evaluation suite before release.
5. **Fast feedback.** Unit and slice tests finish in under 5 minutes on a pull request; slower suites run nightly.

## 2. Test levels

| Level | What | Tools | Runs |
| --- | --- | --- | --- |
| Unit (Java) | Domain logic: rights state machine, credit ledger, price bands, quota counters, ledger hashing, Unicode normalisation | JUnit 5, AssertJ, Mockito | Every pull request |
| Slice and integration (Java) | Controllers, repositories, queue, webhooks against real PostgreSQL, Valkey and S3-compatible storage | Spring Boot Test, Testcontainers (PostgreSQL, Valkey, MinIO), WireMock for provider APIs | Every pull request |
| Architecture rules | Module boundaries in the modular monolith | ArchUnit | Every pull request |
| Unit (Python workers) | Pre- and post-processing, job handling, loudness, watermark calls | pytest | Every pull request |
| Contract | API matches OpenAPI; web client uses only published endpoints | springdoc OpenAPI plus schema tests | Every pull request |
| Web unit | Components and hooks | Vitest, Testing Library | Every pull request |
| End to end | Core flows in PRD section 7 | Playwright (Chromium, WebKit, mobile viewport) | Nightly and before release |
| Accessibility | WCAG 2.2 AA automated checks; manual screen-reader passes | axe-core with Playwright; NVDA, VoiceOver, TalkBack | Nightly (automated); each release (manual) |
| Performance and load | Latency SLO, queue behaviour, scaling | k6 | Before beta and each release |
| Security | SAST, dependency, image and secret scans, DAST, authorisation tests | Semgrep, SpotBugs with Find Security Bugs, Trivy, Gitleaks, OWASP ZAP | See threat model section 6 |
| Model evaluation | Prompt adherence, technical audio checks, language check, similarity, safety red team | pytest with librosa, pyloudnorm, ASR model | Nightly and on any model change |
| Listening tests | Gate G1 blind preference tests | Web form with randomised pairs | Before beta, per language |

## 3. Test data

| Data set | Contents | Rules |
| --- | --- | --- |
| Prompt set | 300 prompts across genres, moods and languages (Hindi Devanagari, Hinglish, English) | Versioned in `test-data/prompts`; no real artist names except in the block-list test set |
| Lyric set | Original lyrics written for testing in each launch language | Written by the team or commissioned; never copied from songs |
| Unicode attack corpus | Homoglyphs, zero-width joiners, mixed scripts, right-to-left overrides | Grows with every bypass found |
| Block-list test set | Artist names in all scripts and spellings | Used only to verify blocking |
| Similarity test set | Pairs labelled "near copy" or "original" | Built from public-domain and royalty-free music only |
| Red-team set | Prohibited content prompts in three languages | Access-restricted folder |
| Audio fixtures | Short clips with known tempo and key | Generated by the team from MIDI |

## 4. Java conventions (JUnit 5)

- Test class per production class, named `<Class>Test`; integration tests named `<Feature>IT` and run by Maven Failsafe.
- Test names state the behaviour: `refusesSixthCommercialLicenceInSameMonth()`.
- Each test method tags its RTM test case with `@Tag("TC-REQ-F-21-01")` so the RTM can be checked automatically.
- Integration tests use Testcontainers with the same PostgreSQL major version as production.
- No sleeps; use Awaitility for asynchronous assertions.

Example of the convention:

```java
@Tag("TC-REQ-F-21-01")
class CommercialLicenceQuotaTest {

    private final Clock clock = Clock.fixed(Instant.parse("2027-01-15T10:00:00Z"), ZoneOffset.UTC);
    private final CommercialLicenceQuota quota = new CommercialLicenceQuota(5, clock);

    @Test
    void refusesSixthCommercialLicenceInSameMonth() {
        UserId user = UserId.random();
        for (int i = 0; i < 5; i++) {
            assertThat(quota.tryConsume(user)).isTrue();
        }
        assertThat(quota.tryConsume(user)).isFalse();
    }
}
```

## 5. Quality gates in CI

A pull request cannot merge unless:

1. All unit, slice, integration, architecture and contract tests pass.
2. Line coverage on changed Java and Python code is at least 80%, and branch coverage of the `rights`, `billing` and `provenance` modules is at least 90% (JaCoCo, coverage.py).
3. No new high or critical findings from SAST, dependency, image or secret scans.
4. The RTM check passes: every test tagged with a TC ID exists in `rtm.csv`, and every P0 requirement in the current sprint has at least one tagged test.
5. One reviewer approves.

## 6. Release gates and exit criteria

| Gate | Test exit criteria |
| --- | --- |
| G1 Model quality | Model evaluation suite green; listening tests meet PRD pass marks for each launch language |
| G2 Beta readiness | All G2 test cases in the RTM pass; zero open launch-blocking BUG items in [review-findings.csv](../registers/review-findings.csv); no serious axe-core violations; load test meets REQ-NFR-01 at 2x expected beta peak |
| G3 Public launch | All G3 test cases pass; external penetration test complete with no open high findings; 4 weeks of beta SLO data; licence scan clean |

## 7. Defect management

| Severity | Definition | Response |
| --- | --- | --- |
| S1 | Data leak, wrong ownership or billing, outage, legal exposure | Fix or roll back immediately; incident process |
| S2 | Core flow broken for a group of users | Fix in the current sprint |
| S3 | Workaround exists | Prioritise in backlog |
| S4 | Cosmetic | Backlog |

Defects use BUG- IDs continuing from the review findings (BUG-091 onward).

## 8. Environments

| Environment | Purpose | Data |
| --- | --- | --- |
| Local | Developer testing with Docker Compose and a small CPU model stub | Synthetic |
| CI | Automated suites | Synthetic; Testcontainers |
| Staging | End to end, load, DAST, listening tests | Synthetic plus invited testers' consented data |
| Production | Beta | Real users; synthetic monitoring only |

A CPU-friendly model stub returns fixture audio so that most tests do not need a GPU.
