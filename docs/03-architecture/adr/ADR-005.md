# ADR-005: Job queue: PostgreSQL first, behind an interface

| Status | Date | Deciders |
| --- | --- | --- |
| Proposed | 2026-10-28 | Founder and developers; drafted by Claude (delegated authority DEC-004, DEC-011) |

## Context

Generation is asynchronous and must survive restarts. Running a separate broker costs money and attention.

## Options considered

1. PostgreSQL table with FOR UPDATE SKIP LOCKED.
2. RabbitMQ.
3. Kafka.
4. Cloud queue service.

## Decision

Option 1 behind a JobQueue interface, with a migration trigger: move to RabbitMQ or Kafka when sustained throughput passes about 50 jobs per second or queue latency affects the API database.

## Consequences

No new infrastructure for the beta; transactional enqueue with the job row. The trigger and interface keep the later migration small.
