# ADR-006: Hosting: free tiers first, containers everywhere, Kubernetes after funding

| Status | Date | Deciders |
| --- | --- | --- |
| Proposed | 2026-10-28 | Founder and developers; drafted by Claude (delegated authority DEC-004, DEC-011) |

## Context

Founders prefer free cloud tiers until funded (DEC-014). GPUs have no free production tier (RISK-004).

## Options considered

1. One hyperscaler from day one on credits.
2. Free tiers across providers, containerised, then consolidate.
3. A single paid VPS.

## Decision

Option 2. Web and API containers on an always-free VM (candidate: Oracle Cloud Always Free ARM, A-030) behind Cloudflare; managed free-tier PostgreSQL or Postgres on the same VM with off-site backups; R2 storage; GPU workers on startup credits or a GPU marketplace with scale-to-zero. Move to Kubernetes (k3s or a managed service) on one provider after funding, using the same container images and OpenTofu definitions.

## Consequences

Near-zero fixed cost, but more providers to watch and free-tier limits that can change (RISK-009). Containers and infrastructure as code keep the move to paid cloud a configuration change, not a rewrite. Free-tier facts must be checked (C-03).
